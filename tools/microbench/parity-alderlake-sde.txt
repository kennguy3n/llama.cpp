# Parity-only AVX-VNNI verification on Intel SDE 9.48 (`-adl` Alder Lake)
#
# Build:
#   cmake -S . -B build-vnni -DLLAMA_MICROBENCH_AVX_VNNI=ON
#   cmake --build build-vnni -j --target microbench-q1-g128-repack
# Run:
#   sde64 -adl -- ./build-vnni/bin/microbench-q1-g128-repack \
#       --blocks 1024 --iters 4
#
# What this checks:
#
#   * Kernel B (gemv_4x4_avx_vnni) is implemented correctly. Every row's
#     output matches the scalar baseline AND the AVX2 4x4 kernel, within
#     FP16 tolerance, after going through `_mm256_dpbusd_avx_epi32` on
#     SDE's instruction-accurate Alder Lake emulator.
#
# What this does NOT check:
#
#   * Performance. SDE dynamically translates VNNI to a host-native
#     sequence; the "gemv_4x4_avx_vnni" timing line below (~570 us /
#     4 rows) is meaningless because each VNNI instruction expands to
#     dozens of host instructions during translation. A real Alder Lake
#     P-core or Zen 4 host is needed to measure true VNNI throughput;
#     that's a follow-up after the harness lands.
#
# What the timing IS valid for: comparing scalar / vec_dot_avx2 /
# gemv_4x4_avx2 to each other (those instructions run natively on
# the AMD EPYC 7763 host SDE is layered on top of). The 1.28x ratio
# between vec_dot_avx2 and gemv_4x4_avx2 holds under SDE too.

microbench-q1-g128-repack: Phase 2 harness for the proposed AVX2/AVX-VNNI
  runtime repack of Q1_0_g128. See docs/avx2-repack-design/03-design-brief.md
  Configuration: nb=1024 (n=131072 weights), iters=4, seed=0xc0ffee

Build features: AVXVNNI AVX2 FMA F16C
